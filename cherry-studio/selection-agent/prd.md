# 划词助手接入智能体 — 产品文档

- 状态：草案，待评审（第 2 版：窗口形态改为「指令条 + 胶囊」）
- 日期：2026-10-27
- 设计稿：[mockups.html](./mockups.html)（浏览器直接打开；右上角可切换浅色/深色）；形态的选择过程见 [directions.html](./directions.html)
- 术语：沿用 `docs/i18n/terminology.md`，界面中文称 Agent 为「智能体」，Assistant 为「助手」

## 1. 背景

划词助手现在只能把选中文本交给**助手**做一次性处理（翻译、解释、总结、自定义提示词）：

- 结果窗口只出一个答案，不能追问，没有输入框；
- 结果放在内存临时话题里，关窗即丢；
- 动作只能绑定助手，用不了智能体的工具、MCP、技能和工作目录。

这些诉求在 issue 里反复出现，过去都是被 stale bot 自动关闭，没有维护者明确拒绝过：

| 诉求 | Issue |
|---|---|
| 划词使用自定义智能体（用例：翻译时把生词写进「单词本」智能体） | #11838 |
| 划词调用 MCP / 工具 | #9239、#6984 |
| 结果窗口追问、连续对话 | #22680（open）、#10950、#11832、#10577、#8051、#6730、#6500 |
| 保存划词历史 | #12431、#7018、#8202 |

相关：#20207（页面级可嵌入 Chat/Agent 对话面板）。

## 2. 目标与非目标

**目标**

1. 在任意应用里选中文本后，可以把它交给智能体去**办事**，过程中能调用工具。
2. 在划词窗口里就能看到智能体的执行过程、批准工具调用、继续追问。
3. 每次交给智能体的工作都是一个**真实会话**，保存在智能体会话列表里，随时可以去主窗口接着做。
4. 智能体在后台干活时，用户不用开着窗口也能看到它的状态，需要批准时能及时发现。

**非目标（本期不做）**

- 不改动现有的助手动作（翻译/解释/总结/优化/自定义助手动作），它们仍然只出一次结果，窗口也不变。助手动作的追问（#22680 的助手部分）留给后续，可以复用本期的窗口结构。
- 不做「用结果替换原文」（#9868、#11352）。
- 不新增智能体运行时能力，只用现有的运行时、工具和审批机制。
- 不在会话上记录「来自划词」的来源标记（见第 11 节待定问题 1）。
- 不在胶囊上直接批准或拒绝工具调用：必须打开窗口看清内容再决定。

## 3. 已定决策

| 决策 | 结论 |
|---|---|
| 会话归属 | 每次划词在选定的智能体下**新建一个真实会话**（conversation 类型），出现在主应用的智能体会话列表里 |
| 窗口形态 | **指令条 → 对话窗口**：唤出时是一条轻量的指令条，发送后向下展开成迷你对话窗口（流式输出、工具调用、审批、追问、「在主窗口打开」） |
| 收起 | 对话窗口可以**收起成胶囊**：最小化（macOS 黄灯、Windows/Linux 最小化按钮）就是收起；胶囊堆叠在屏幕右下角（各平台统一），显示状态，点击恢复 |
| 窗口外壳 | 去掉标题栏色带，头部由我们绘制，整窗只用一种背景（popover）。macOS 保留系统红绿灯并嵌进头部 |
| 触发方式 | **两种都要**：工具栏内置「问智能体」（用户自己写指令）+ 自定义动作绑定智能体（提示词模板，一键执行） |
| 关窗语义 | **关窗不停止**。这一轮在后台继续执行，会话持久化保存，可以在主应用里看到运行和待批准状态 |
| 失焦 | 开启「自动关闭」时，运行中和待批准的窗口失焦后**收成胶囊**，其他状态照常关闭 |

## 4. 用户场景

**场景 A：问智能体（自由指令）**
小林在终端里看到一段报错。选中报错 → 点工具栏「问智能体」→ 指令条弹出，报错已作为引用显示在顶部 → 输入「这个报错是什么原因？在项目里查一下」，工作目录选 `my-blog` → 回车。指令条向下展开成对话窗口，智能体搜索、读文件。小林切回编辑器继续写代码，窗口失焦收成右下角的胶囊，显示「第 3 步」。过了一会儿胶囊变成「完成」，小林点开胶囊看到原因和修改建议，又追问「帮我改掉」，智能体请求编辑文件，小林在窗口里点「允许」。

**场景 B：绑定智能体的自定义动作（一键执行）**
小周给自定义动作「加入单词本」绑定了自己的「单词本」智能体，提示词是「把下面文本里的生词加入单词本，并给出音标和释义：{{text}}」。阅读英文网页时选中一段 → 点「加入单词本」→ 对话窗口直接打开并开始执行。小周点黄灯把它收起，继续阅读；胶囊很快变成「等你批准」并移到离角落最近的位置 → 点开胶囊，窗口恢复，审批卡片显示要写入 `vocabulary.md` 的内容 → 允许 → 完成。晚上在主应用「单词本」的会话列表里还能找到这次记录。

## 5. 入口

### 5.1 工具栏「问智能体」

- 新的内置动作，id 暂定 `ask-agent`，图标 `bot`，名称「问智能体」/ "Ask Agent"。
- 点击后打开**指令条**（待输入状态，见 6.2）：选中文本作为引用显示在顶部，光标停在输入框，**不会自动发送**。
- 在动作列表里和「搜索」一样，名称旁显示当前默认智能体，并有设置入口，点开是「问智能体设置」弹窗：
  - 默认智能体：默认是内置的 Cherry Assistant；
  - 默认工作目录：默认「不使用工作目录」。
- 新装用户默认启用；老用户在设置的动作列表里能看到，但默认不启用，避免挤占工具栏现有位置。

### 5.2 自定义动作绑定智能体

- 自定义动作编辑弹窗里，「模型」单选从「默认模型 / 使用助手」扩展为「默认模型 / 使用助手 / **使用智能体**」。
- 选「使用智能体」后，表单显示：
  - 选择智能体（必选）；
  - 工作目录（默认「不使用工作目录」）；
  - 提示词：沿用现有规则，支持 `{{text}}`；没写 `{{text}}` 时把选中文本接在提示词后面。
- 选中时显示一行说明：「智能体会新建会话并可能调用工具，会话保存在该智能体的会话列表中。」
- 动作列表里，绑定了智能体的动作在名称旁显示智能体名。
- 点击动作后**跳过指令条**，直接打开对话窗口并发送，进入启动中/运行中状态。

### 5.3 不变的部分

翻译、解释、总结、优化、搜索、复制、引用以及绑定助手的自定义动作，行为和窗口都不变。

## 6. 智能体窗口

### 6.1 外壳

- **没有标题栏色带。** 头部（高 44px）由我们绘制，和内容区同一背景（popover）；头部、内容、输入区之间只用间距和细分隔线区分。头部空白处可以拖动窗口。
- **macOS**：保留系统红绿灯，嵌进头部左侧并和头像垂直居中（左侧预留 78px）。红灯 = 关闭，黄灯 = 收起成胶囊（见 6.7），绿灯保持系统行为。
- **Windows / Linux**：没有红绿灯，头部右侧由我们绘制最小化和关闭。最小化的提示文字是「收起为胶囊」，行为和 macOS 黄灯一致。
- **头部右侧**（各平台相同）：在主窗口打开、置顶、透明度（沿用现有的透明度滑杆）。
- **选中文字**在窗口里一律用 `--reference` 底色标出，和来源应用里的选区呼应，也不会和「等待批准」的 warning 色混淆。

### 6.2 指令条（待输入）

- 宽 560，高度随内容（约 150），没有单独的头部。
- 第一行：红绿灯、选中文字引用（只显示一行，悬停看全文，悬停时出现 ✕ 可移除）、来源应用和行数/字数。
- 第二行：大号输入框，占位文字「让智能体做什么？」。
- 第三行：智能体选择、工作目录选择（默认取「问智能体设置」，可以临时改）；右侧是一行小字「会保存为会话」和发送按钮。
- 这时还没有会话，所以**不能收起**：macOS 黄灯置灰，Windows/Linux 的指令条只有关闭。
- 没有可用智能体时，输入行换成说明「还没有智能体。创建一个后，就能把选中的文字交给它处理。」，右下角是「创建智能体」，点击后在主窗口打开创建流程。正常情况下内置的 Cherry Assistant 一直存在，只有它被删除时才会出现这个状态。

### 6.3 对话窗口

发送后，指令条**向下展开**成对话窗口：顶边位置不变，窗口长高；下方空间不够时，保持底边不动向上长高。引用和指令原地变成第一条消息，头部随之出现。智能体动作（5.2）直接以对话窗口打开，没有展开过程。

从上到下：

1. **头部**：红绿灯（macOS）、智能体头像 +「智能体名 · 会话名」（会话名沿用现有的首条消息自动命名）、状态标签（待批准时显示「等待批准」）；右侧按钮见 6.1。
2. **消息区**（下面前两条是体验后的目标呈现；第一版先复用主窗口的消息渲染、工具卡片和审批区）：
   - 第一条消息不是气泡：指令（或动作名 + 动作图标）作标题，下面一行是引用（`--reference` 底色）+ 来源应用 + 展开按钮，点开看全文；之后一条细分隔线。
   - 智能体回复：文本 + 紧凑的工具调用步骤行（状态图标、工具名、目标），点开看输入输出；错误提示。
   - 新内容到达时自动滚到底部；用户上翻后停止自动滚动，沿用现有规则。
3. **输入区**：输入框，右侧只读显示工作目录，以及发送/停止按钮。有待批准的工具调用时，输入区整体换成审批卡片，和主窗口相同。

### 6.4 状态

| 状态 | 形态 | 进入条件 | 界面 |
|---|---|---|---|
| 待输入 | 指令条 | 点「问智能体」 | 见 6.2 |
| 没有智能体 | 指令条 | 待输入时没有可用智能体 | 见 6.2 |
| 启动中 | 对话窗口 | 已发送，运行时还没开始输出 | 第一条消息 +「正在启动 {智能体名}…」 |
| 运行中 | 对话窗口 | 有文本或工具调用在流式输出 | 回复逐步出现；工具调用是步骤行；输入框可用，输入框为空时按钮是停止 |
| 待批准 | 对话窗口 | 工具调用需要用户批准 | 审批卡片替换输入区：工具名、参数预览、拒绝原因输入、「拒绝」「允许」；头部显示「等待批准」 |
| 完成 | 对话窗口 | 本轮结束 | 最后一条回复下方有「复制」「在主窗口继续」；输入框提示「继续追问…」 |
| 错误 | 对话窗口 | 本轮失败 | 消息流里出现错误提示（error-subtle 样式），已知原因给出针对性操作（见 6.10） |

失焦、最小化、Esc 在各状态下的行为见 6.6 的规则表。

### 6.5 智能体收到的内容

- **问智能体**：用户写的指令 + 选中文本引用。引用会注明来源应用（例如「选中自 Google Chrome」），来源应用名取自划词事件里的 `programName`。
- **自定义动作**：按提示词模板拼出的文本，规则和助手动作一致。
- 选中文本会作为用户消息**持久化保存**。这和助手动作只存在内存里不同，所以指令条上要有「会保存为会话」的提示，设置里也有说明。

### 6.6 追问、键盘与窗口规则

**追问与运行中输入**

- 完成后在输入框继续输入，就是同一会话里的下一轮。
- 运行中也可以输入并发送。消息会作为补充说明在当前步骤之后送达（沿用智能体会话现有的 follow-up 机制），这时输入框提示「补充说明，将在当前步骤后送达」。
- 小窗**暂不支持排队**：运行中发送一律直接插话，由主进程立即保存，关窗也不会丢；代价是发出后不能再编辑或撤回。主窗口输入框的排队目前只存在本窗口内存里，关窗会丢，要等队列搬到主进程统一管理（#22824）后再支持。
- 停止：运行中点停止按钮，或按 `Esc`。

**键盘**

| 按键 | 行为 |
|---|---|
| `Enter` / `Shift+Enter` | 发送 / 换行 |
| `Enter`（待批准） | 允许；填写了拒绝原因时为拒绝（审批卡片现有行为） |
| `Esc` | 见下表 |
| `⌘M`（macOS） | 同黄灯：收起成胶囊 |

**规则表**

| 状态 | 失焦（开启自动关闭时） | 黄灯 / 最小化 | Esc | 在主窗口打开 | 新的划词触发 |
|---|---|---|---|---|---|
| 待输入（有草稿） | 不关闭 | 不可用 | 不响应，避免误关丢稿 | 不可用 | 另开窗口 |
| 待输入（空） | 关闭 | 不可用 | 关闭 | 不可用 | 复用这个窗口 |
| 启动中 / 运行中 | **收成胶囊** | 收成胶囊 | 停止 | 可用 | 另开窗口 |
| 待批准 | **收成胶囊** | 收成胶囊 | 拒绝（审批卡片现有快捷键） | 可用 | 另开窗口 |
| 完成 / 错误 | 关闭 | 收成胶囊 | 关闭 | 可用 | 复用这个窗口 |
| 已收成胶囊 | — | — | — | 恢复后可用 | 不复用 |

- 置顶的窗口失焦时不做任何处理，沿用现有规则（置顶时不自动关闭）。
- **尺寸**：指令条 560 宽、高度随内容；对话窗口默认 560×620，最小 420×480。「记住窗口大小」开启时，对话窗口单独记住自己的尺寸，和助手结果窗口分开。
- **位置、置顶、透明度、自动置顶**：和现有结果窗口一致。
- **多窗口**：一个窗口对应一个会话。另开的窗口错开位置。
- **动效**：展开（指令条向下长高）和收起（窗口朝胶囊位置缩小淡出）都要有过渡；开启「减少动态效果」时直接切换。

### 6.7 胶囊

- **收起**：黄灯 / 最小化 / `⌘M`，或开启自动关闭时运行中、待批准的窗口失焦。收起不停止智能体。
- **位置**：各平台统一堆叠在窗口所在显示器的右下角，按可用区域（`workArea`）定位，自动避开程序坞和任务栏，距边缘 12px。和划词窗口一样置顶，全屏应用上也能看到。
  - 不放右上角：那里是 macOS 系统通知滑出的位置，也是 Windows/GNOME 最大化窗口关闭按钮的位置。
  - 右下角在 Windows 和部分 Linux 桌面上会和系统通知暂时重叠；通知是短暂的，可以接受。
  - macOS 从 Monterey 起右下触发角默认是「快速备忘录」。胶囊离边缘 12px，正常点击碰不到，只有鼠标甩进角落才会触发，影响很小。
- **排序**：从角落向上堆叠。离角落最近的是等你批准，往上依次是运行中、完成 / 出错；同类按收起时间排列。
- **内容**：智能体头像 + 智能体名 + 状态：
  - 运行中：「第 N 步」（按工具调用计数）；还没有工具调用时显示「运行中」；
  - 等你批准：warning 底色，排在离角落最近的位置；
  - 完成 / 出错：一直保留，直到用户点开查看或手动关掉，因为里面有还没看的结果。
- **悬停**：多显示会话名，并出现 ✕。点 ✕ 等同于关闭窗口（6.8）。
- **点击**：窗口按收起前的位置和大小恢复，胶囊消失。
- **数量**：最多显示 5 个，其余折叠成「+N」，放在堆叠的最上面，点击展开全部。
- **生命周期**：胶囊只存在于这次运行期间。退出 Cherry Studio 后胶囊消失，会话照常保存在主应用里。

### 6.8 关窗与后台运行

- **关窗不停止。** 关窗（红灯、关闭按钮、胶囊上的 ✕）只是不再显示，也不留胶囊，这一轮在后台继续，结果持久化保存。只有「停止」才会中止。
- **在主应用里可见。** 会话出现在对应智能体的会话列表里，列表项显示运行中 / 等待批准状态（会话列表已有这些状态标记）。用户打开会话就能看到全部过程，也能在那里审批。
- 待输入时关窗：没有发送就不会创建会话，草稿直接丢弃。

### 6.9 在主窗口打开 / 在主窗口继续

- 把主窗口带到前台，打开智能体页面并选中这个会话。
- 迷你窗口和它的胶囊随即关闭，正在进行的这一轮不受影响。
- 输入框里没发送的草稿会带到主窗口的输入框里。
- 待输入状态下（会话还没创建）这个按钮不可用。

### 6.10 错误处理

| 情况 | 提示 | 操作 |
|---|---|---|
| 智能体没有配置模型 | 「{智能体名} 还没有配置模型」 | 「去配置」→ 在主窗口打开智能体设置 |
| 运行时未安装（如 Claude Code） | 「{运行时} 尚未安装」 | 「前往安装」「重试」 |
| 绑定的智能体已被删除或归档 | 「动作绑定的智能体不可用」 | 「编辑动作」→ 打开划词设置 |
| 其他运行错误 | 运行时返回的错误信息 | 「重试」「在主窗口打开」 |

## 7. 设置变更汇总

| 位置 | 变更 |
|---|---|
| 划词助手 → 动作列表 | 新增内置动作「问智能体」，名称旁显示默认智能体，附带设置弹窗（默认智能体、默认工作目录）；绑定智能体的自定义动作名称旁显示智能体名 |
| 自定义动作编辑弹窗 | 模型单选增加「使用智能体」，选中后显示智能体、工作目录、提示词 |
| 窗口相关设置 | 不新增设置项；6.6 的失焦和收起规则是固定规则 |

## 8. 会话与数据

- 只在**第一次发送**时创建会话：在选定的智能体和工作目录下新建 conversation 会话，不会留下空会话。
- 会话和主窗口里新建的会话没有区别：可以重命名、置顶、归档、删除，也可以在主窗口继续对话。
- 动作绑定智能体后，自定义动作的数据需要记录智能体 id 和工作目录，具体字段在 Spec 里定。
- 胶囊不落库：它只反映当前窗口和会话的运行状态（见 6.7 生命周期）。

## 10. 验收标准

1. 选中文本 → 点「问智能体」→ 指令条出现：引用显示选中文本和来源应用，光标在输入框，没有自动发送；黄灯不可用。
2. 待输入时直接关闭，智能体会话列表里不会多出新会话。
3. 写指令发送后：指令条向下展开成对话窗口；选定的智能体下多出一个新会话，包含选中文本和指令；窗口里能看到流式回复和工具调用步骤。
4. 点绑定智能体的自定义动作 → 直接以对话窗口打开并开始执行；提示词按 `{{text}}` 规则拼接。
5. 窗口没有标题栏色带，整窗同一背景；macOS 红绿灯在头部内和头像对齐；Windows/Linux 头部右侧有最小化和关闭。
6. 运行中或待批准时点黄灯 / 最小化：窗口收成右下角的胶囊（不压住程序坞或任务栏），智能体继续执行，胶囊状态随之更新（第 N 步 → 等你批准 → 完成）。
7. 开启自动关闭时，运行中或待批准的窗口失焦后收成胶囊；完成、错误、空闲的窗口失焦后关闭；有草稿的指令条失焦不关闭。
8. 点胶囊：窗口按原来的位置和大小恢复，胶囊消失；多个胶囊从角落向上按「等你批准 → 运行中 → 完成/出错」排列，超过 5 个折叠成「+N」。
9. 工具需要批准时，输入区换成审批卡片；允许或拒绝后这一轮继续。
10. 运行中关窗（红灯或胶囊 ✕）：不留胶囊，这一轮继续执行；主应用会话列表显示运行中；结束后打开会话，内容完整。
11. 待批准时关窗：主应用会话列表显示等待批准；在主窗口打开会话后可以审批，审批后继续执行。
12. 完成后在窗口里追问，会作为同一会话的下一轮。
13. 「在主窗口打开」：主窗口打开并选中这个会话，迷你窗口和胶囊关闭，未发送的草稿出现在主窗口输入框里。
14. 一个窗口还在运行或已收成胶囊时又触发一次智能体，会另开一个窗口，原窗口不受影响。
15. 开启「减少动态效果」时，展开和收起直接切换，没有过渡动画。
16. 现有助手动作（翻译、解释等）的行为和窗口不变。
17. 浅色和深色模式下都使用语义 token，符合 DESIGN.md 的检查清单。

## 11. 待定问题

1. **会话来源标记**：要不要在会话列表里标出「来自划词」？需要给会话加来源字段（schema 变更 + 迁移）。建议本期不做。
2. **系统通知**：胶囊已经能在桌面上显示「等你批准」，但窗口已关闭（没有胶囊）时，进入等待批准要不要发系统通知？建议本期不做，先观察反馈。
3. **来源应用名发给模型**：`programName` 写进引用会把「用户在用什么应用」发给模型提供商。建议发送，因为它显示在引用旁，用户看得到，也可以移除引用。
4. **在主应用里看过结果后胶囊怎么办**：用户在主应用打开了同一个会话时，对应的「完成」胶囊要不要自动消失？建议消失，和「在主窗口打开」的行为一致。
5. **待输入时的快捷建议**：要不要在指令条里把绑定智能体的自定义动作列成快捷按钮？建议后续再做。
6. **内置「解释/总结」能否切到智能体**：建议不做，想要的话用自定义动作。

## 12. 实现风险（交给 Spec 处理）

- **组件复用**：智能体页面的消息列表、输入框、审批卡片能否嵌进独立窗口，要看它们和 tab/路由的耦合。如果需要先做一个上游的「可嵌入会话视图」，就和 #20207 一起评估，不在划词这边绕过去。
- **macOS 黄灯接管**：Electron 的 `minimize` 事件不能取消，黄灯默认会把窗口最小化到 Dock。需要在 native 层（参考 `native/darwin/selectionPanel.mm`）改写最小化行为，或评估其他方案；Spec 里先验证可行性。
- **胶囊窗口**：新的窗口类型，要在 `windowRegistry` 里登记。倾向每块显示器一个透明的容器窗口装下所有胶囊，透明区域点击穿透；全屏应用和多个 Space 下的显示参考现有划词工具栏的处理。
- **胶囊状态来源**：窗口收起后，胶囊仍要实时拿到会话的运行状态（运行中、等待批准、步数、完成、出错），状态来源在 Spec 里定。
- **展开/收起动效**：macOS 可以用 `setBounds(…, animate)`；Windows/Linux 要分帧调整窗口大小，需要评估流畅度和成本。
- **冷启动延迟**：Claude Code / Pi 第一轮启动有延迟，所以设计了「启动中」状态。智能体动作的定位是办事，不替代翻译这类要求秒出的动作。
- **窗口池**：现有结果窗口是池化复用的，而智能体窗口要遵守 6.6 的「另开窗口」规则，收成胶囊的窗口也不能被复用，需要单独的窗口类型或池化策略。
