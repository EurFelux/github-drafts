迷你智能体窗口 · 三个方向

2026-10-27 · 示例内容沿用文档里的两个场景

已定：A 的指令条 + C 的胶囊。唤出时是指令条，发送后展开成对话窗口；最小化或失焦后收成屏幕右下角的胶囊（和方向 C 不同，避开系统通知和最大化窗口的关闭按钮）。定稿见 mockups.html 和 prd.md，本页保留作选择记录。

去掉标题栏色带头部由我们绘制，和内容区同一背景。macOS 保留系统红绿灯，嵌在头部左侧并垂直居中（左侧预留 78px），关闭和最小化用系统的；Windows/Linux 没有红绿灯，头部右侧由我们绘制最小化和关闭。头部空白处可以拖动。
整窗一种背景整个窗口只用 popover 表面。头部、内容区、输入区之间不再用色带区分，只靠间距，必要时加一条细分隔线。
引用标记选中的文字带着 --reference 底色进入窗口（浅色模式蓝色，深色模式灰色），和来源应用里的选区呼应，也不会和「等待批准」的琥珀色混淆。
不变的部分颜色、字体都用 Cherry 的 token；产品规则（会话、关窗、审批）和 prd.md 一致，这里只换形态。
方向 A

指令条：先是一条输入栏，发送后向下展开

待输入时窗口只是一条输入栏，像启动器一样轻；发送后向下展开成完整窗口。展开后的内容区和审批卡片沿用主窗口的对话样式。

方向 B

任务单：上面写要做什么，下面一步步记录怎么做

推荐

不做成聊天。顶部是这次任务（指令 + 引用），下面是一条按顺序排列的步骤轴，审批卡片就放在被拦下的那一步上；完成后步骤收起，结果成为主角。

方向 C

贴边伴随：窗口贴在屏幕右侧，收起后变成状态胶囊

窗口不再跟着选区弹出，而是贴在屏幕右侧，像一个随叫随到的侧栏。关掉不是消失，而是收成右上角的小胶囊，后台任务的状态一直可见。

内容的组织方式对话流，和主窗口一致任务 → 步骤 → 结果，不是对话对话流，放在侧栏里
审批的位置替换输入区（和主窗口一致）放在被拦下的那一步上替换输入区
复用主窗口组件最多：消息列表、输入区、审批卡片工具渲染、Markdown、审批卡片内容；步骤轴是新的组合和 A 相同
新增工作窗口从输入栏展开的动效（Windows/Linux 较难做）步骤轴布局、完成后收起贴边窗口、胶囊窗口、多任务切换、多显示器定位
和已定规则的关系一致一致要改关窗规则，范围变大
当时的推荐是 B（最终没有采用，见页首）。智能体干活和聊天不一样：用户想知道它在做哪一步、卡在哪里、最后得到了什么，任务单正好按这个顺序组织。审批放在被拦下的那一步上，比放在输入区更容易看懂。B 只用一个固定窗口，没有 A 的跨平台动效问题，也不需要 C 的新窗口类型。A 待输入时那种轻巧的输入栏，以后可以作为 B 的待输入形态再评估；C 的胶囊适合等后台任务多起来以后单独立项。
